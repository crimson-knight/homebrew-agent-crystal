LLVM's native deletion contract is explicit: `LLVMDisposeMemoryBuffer` deletes the buffer (Core.cpp:4564–4566). It may release malloc storage or a mapping; allocator retention can keep process RSS high afterward. A lower outstanding-owned-payload total is therefore a mechanism result, not a promised RSS decrease.

The smallest safe library correction makes the finalization guard transition occur in the operation that actually calls native disposal, so explicit disposal, repeated disposal and later finalization reach exactly one release. The consuming-IR path also needs an explicit ownership-transfer operation and an unusable-wrapper state. Keep these two semantics distinct in the registry. Actual API/type/format/spec tests precede any compiler intervention. The source model's proposed text is an uncompiled sensitivity model, not an accepted patch.

The native probe should use a small checksum-pinned C shim with unique diagnostic symbols. Register successful buffer creation with a bounded numeric handle registry and `LLVMGetBufferSize`; increment disposal-entered and disposal-completed around the real pinned LLVMDisposeMemoryBuffer call. Record transfers separately. A creation/deletion hook that merely updates a counter without executing LLVM is a failed control. For consumed IR, a transfer retires *caller ownership*; native destructor/free observations require independent allocator evidence and cannot be inferred from a missing C disposal call.

Run original, fixed and restored wrappers against the same useful known buffer/bitcode cases: 64 owned 1-MiB copies, explicit double-dispose followed by a GC-finalizer pass, natural finalization, valid/invalid eager borrowed bitcode, and valid/invalid consuming IR. Retain actual native call and completion counts, registered/outstanding/transferred payload bytes, use-after-transfer refusal, valid parsed-module verification and exact output behavior. Add a deliberately skipped native release as a sensitivity control and a duplicate-release canary intercepted before invoking LLVM twice. Keep each native case in its own bounded original process group so a crash retains raw evidence.
